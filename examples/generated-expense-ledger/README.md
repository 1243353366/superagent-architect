## What it does

A personal expense ledger for tracking monthly spending.

## Resources and API

Each resource exposes JSON CRUD over HTTP:

| Method | Path | Purpose |
|---|---|---|
| GET | /api/expenses | List |
| POST | /api/expenses | Create |
| GET | /api/expenses/<id> | Read one |
| PUT | /api/expenses/<id> | Update (partial) |
| DELETE | /api/expenses/<id> | Delete |
| GET | /health | Health check |
| GET | / | Single-page UI |

## Run

```bash
python run.py
# serving on http://127.0.0.1:8000
```

Environment variables (see .env.example — never commit real secrets):

- APP_HOST (default 127.0.0.1)
- APP_PORT (default 8000)
- APP_DB (default app.db)

## Test

```bash
python -m unittest discover -s tests -v
```

Tests start a real server on an ephemeral port and exercise CRUD, validation,
error handling, and persistence across a simulated restart.

## Data model

SQLite, single file (APP_DB), versioned migrations applied automatically at
startup (see app/storage.py). Fields per resource: id, title, notes, done,
created_at.

## Security notes

- Input is validated at the boundary; unknown fields are rejected (deny-by-default).
- No authentication layer is generated: keep this service behind a trusted
  boundary or add auth before exposing it.
- No secrets are committed; configuration comes from environment variables.
